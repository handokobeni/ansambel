# 2026-05-16 — Phase 3a-3.1 view-aware Lark binding

Ansambel now honors Lark Bitable per-view filters. Bindings gain an optional
`view_id`; the wizard exposes a new Step 1.5 view picker; view-deletion falls
back gracefully with a non-blocking banner.

**Why this was needed:** during manual testing post-PR #26, the bound table held
667 records across all sprints. Ansambel's kanban showed 186 TODO cards while
Lark's "Current Sprint" view showed 11. View filters live on the view in Lark,
not the table — and Ansambel was fetching the whole table. This phase threads
optional `view_id` through every layer.

**Scope:**

- Backend: `BitableView` type, `bitable_list_views` helper, `list_lark_views`
  Tauri command. `bitable_list_records` accepts optional `view_id`.
  `BitableBinding` gains `view_id: Option<String>` (schema v1 → v2,
  `#[serde(default)]` so legacy bindings load as `None`).
- `LarkProvider`: threads `view_id` through `list_tasks`. On Lark code
  `1254045 ViewNotFound`, retries unfiltered + emits `lark-view-missing` via
  injected `ViewMissingSink` trait.
- Frontend: wizard Step 1.5 (view picker), `RepoSettingsDialog` "View:" row,
  `viewMissing` Svelte store, TitleBar banner with Reconfigure / Dismiss.

**Tests:** 13 new unit + 4 component + 1 store + 2 integration + 2 E2E
(env-gated). All 611 lib tests pass, all 745 frontend tests pass.
