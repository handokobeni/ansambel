bahwa ansambel sudah strictly lebih baik di backend (10 AgentEvent variant vs 4,

**Token UX fix (bug yang dilaporkan user hari ini).**

User laporkan: "tanya biasa saja sudah habis 900k token". Investigasi tracing
pipeline:

1. Backend parser (`agent_stream.rs:316`) per assistant message:
   `total_input = input + cache_creation + cache_read` ✓ benar per-pesan, sesuai
   hard-rule "sum 3 sumber".
2. Frontend store accumulator (`messages.svelte.ts:145`):
   `inputTokens += ev.total_input` cumulative lintas semua assistant message
   dalam satu turn ❌ inilah biangnya.

Di Claude Code, system prompt + tools + repo context biasanya 30–100 k token
yang dicache. Setiap step dalam multi-step turn (assistant → tool_use →
tool_result → assistant lagi) menerbitkan satu Usage event yang
`cache_read_input_tokens` ≈ ukuran cache penuh, karena tiap step **membaca
ulang** isi cache yang sama. Kalau turn punya 9 step dan masing-masing report
`cache_read = 100k`, total akumulasi = **900k token** — meskipun tokennya
benar-benar "biasa". Itu konten yang sama dibaca berulang dari cache (dibilling
10% dari harga input normal), bukan 900k token "baru".

Fix: `TurnState` di-split jadi tiga counter:

| Counter            | Akumulasi                                    | Billing         |
| ------------------ | -------------------------------------------- | --------------- |
| `inputTokens` (↓)  | `input_tokens + cache_creation_input_tokens` | full input rate |
| `cachedTokens` (↻) | `cache_read_input_tokens`                    | 10% input rate  |
| `outputTokens` (↑) | `output_tokens`                              | output rate     |

`TurnStatusBar` render tiga chip terpisah: `↓ 450 · ↻ 900.0k · ↑ 1.8k`. Chip `↻`
di-style lebih redup (`text-[var(--text-dim)]`) dan tidak muncul kalau
`cachedTokens === 0` (turn pertama session). Tooltip pada `↓` menjelaskan "Fresh
input: …" agar user paham apa yang dihitung. Hard-rule "sum 3 sumber" tetap
valid per-pesan di backend (tidak diubah); yang berubah hanya cara frontend
mengakumulasi lintas multi-step.

Regression guard
`does NOT inflate inputTokens by accumulating cache_read across steps` di
`TurnStatusBar.test.ts` mengunci behavior — 9 step × 100k cache_read → `↓ 450` +
`↻ 900.0k`, bukan `↓ 900k`.
